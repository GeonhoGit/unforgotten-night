- 복원 버튼이나 다른 버튼을 눌러 화면을 갱신해도 창 내부 스크롤이 맨 위로 초기화되지 않아야 합니다. 상세 펼침 상태와 가로 스크롤도 보존합니다.
- 어두운 분위기에 맞춘 스크롤바를 유지합니다.
- 사진 확대 팝업은 바깥 배경을 클릭하면 닫힙니다. 안쪽에서 시작한 드래그가 바깥에서 끝난 경우에는 닫히지 않습니다.

## 상태와 저장 주의사항

저장 키는 `used-pc-mystery:ep1:v3`, schemaVersion은 3입니다. 이전 `used-pc-mystery:ep1:v2`는 보존하지만 새 구조로 자동 변환하지 않습니다. 새 버전의 최초 이용에는 새 조사가 필요합니다.

브라우저 저장은 컴퓨터·브라우저·사이트 주소별로 분리됩니다. 소스를 복사해도 플레이 진행은 옮겨지지 않습니다. 진행을 옮겨야 한다면 기존 브라우저 개발자 도구의 Local Storage에서 해당 v3 키 값을 별도 백업한 뒤 같은 게임 버전의 대상 브라우저에 복사해야 합니다. 게임 안의 저장 내보내기·가져오기 기능은 아직 없습니다.

P5 완료는 stage 5로 보존합니다. F10을 아직 안 읽었다면 마지막 메일 확인으로 연결하고, 읽은 뒤 인계 준비로 연결해야 합니다. `prepareHandoff`는 첫 준비 때만 누락 복원·handoffPrepared·cpFinal을 함께 설정하며 반복 호출로 체크포인트를 덮어쓰지 않습니다. 최종 선택은 `canFinalize`를 통과해야 합니다. 증언자 선택은 F13 열람이 필요합니다.

예상 플레이 시간 30~60분은 기획 목표이며 실제 신규 플레이어 실측은 하지 않았습니다. 여러 브라우저 전체 호환성과 대규모 플레이테스트는 미검증입니다.

## 기존 사이트에 다시 배포하기

같은 사이트 소유 계정으로 Codex에 로그인하고 Sites 플러그인을 사용할 수 있어야 합니다. 로컬 실행에는 Sites가 필요하지 않습니다. 인증 토큰을 문서나 코드에 저장하지 마세요.

기존 `.openai/hosting.json`의 프로젝트 ID를 재사용합니다. 새 사이트를 만들지 않습니다. Sites 스킬을 읽고, 소스를 커밋한 뒤 해당 프로젝트의 새 단기 저장소 인증을 발급받아 지정된 저장소·브랜치에 푸시합니다. 푸시 성공 후 `git rev-parse --verify HEAD`의 전체 SHA를 사용합니다. 정확히 그 소스의 `dist`와 호스팅 설정을 패키징해 버전을 저장하고, 반환된 버전 ID로 소유자 전용 배포를 수행합니다. 배포 성공 상태를 확인한 뒤 완료를 보고합니다.

ZIP에는 Git 이력이 없으므로 기존 원격 저장소를 인증 후 복제하는 방법을 우선합니다. Sites가 반환한 저장소 URL을 사용하고, 수정 파일만 적용하세요. 강제 푸시로 원격 이력을 덮어쓰지 마세요.
